# Deploying the demo

The demo runs on two free services:

| Part | Host | Notes |
|---|---|---|
| Django API | [Render](https://render.com) free web service | Sleeps after 15 minutes without traffic; the next visit waits up to a minute while it starts |
| React app | [Vercel](https://vercel.com) Hobby | Static site served from Vercel's CDN |

By default the API uses a SQLite database that is built and seeded during each Render build.
Every deploy, and every wake-up after the service has slept, starts from the same clean demo
data, which suits a public demo that anyone can sign in to. To keep changes instead, create a
free PostgreSQL database (for example on [Neon](https://neon.com)) and set `DATABASE_URL`.

Uploaded attachments are stored on the web service's disk and disappear on restart.

## 1. API on Render

1. Sign in to Render with GitHub and choose **New → Blueprint**.
2. Pick the `ai-form-assistant` repository. Render reads [`render.yaml`](../render.yaml) and
   creates the `ai-office-assistant-api` web service.
3. Fill in the variables Render asks for:

   | Variable | Value |
   |---|---|
   | `OPENAI_API_KEY` | Your OpenAI key. Set a monthly usage limit in the OpenAI dashboard as well. |
   | `CORS_ALLOWED_ORIGINS` | The Vercel URL from step 2, e.g. `https://ai-form-assistant.vercel.app`. Leave it empty for now and fill it in after step 2. |
   | `FRONTEND_URL` | The same Vercel URL (used in password reset emails). |
   | `DATABASE_URL` | Leave empty for the self-resetting SQLite demo, or paste a PostgreSQL URL. |

4. Apply. The first build installs packages, collects static files, migrates and seeds the
   demo data. When it is live, `https://<service>.onrender.com/api/v1/health/` returns
   `{"status": "ok"}`.

`SECRET_KEY` is generated by Render. `THROTTLE_RATE_AI` limits each account to 30 AI requests
per hour, since the demo accounts are shared.

## 2. Frontend on Vercel

1. Sign in to Vercel with GitHub and choose **Add New → Project**, then import the repository.
2. Set **Root Directory** to `frontend`. Vercel detects Vite.
3. Add the environment variable `VITE_API_URL` = `https://<service>.onrender.com/api/v1`.
4. Deploy. [`frontend/vercel.json`](../frontend/vercel.json) sends every route to `index.html`,
   so reloading a page such as `/dashboard` works.

Then go back to Render and set `CORS_ALLOWED_ORIGINS` and `FRONTEND_URL` to the Vercel URL.
Render redeploys with the new values.

## 3. Check it

Open the Vercel URL and sign in as `john_doe` / `User123!`. If the API was asleep, the login
page says it is starting it. After a minute the demo data is available.

## Keeping costs at zero

- OpenAI is the only paid part. Shared demo accounts mean anyone can use the AI features, so
  set a usage limit on the key.
- Render's free plan includes 750 instance hours per month, which covers one always-available
  service. Render suspends free services once a workspace uses up its hours.
- Render's own free PostgreSQL expires after 30 days, which is why the default is SQLite and
  the alternative is an external database such as Neon.

## Running in production mode locally

```bash
cd backend
DEBUG=False SECRET_KEY=local-test ALLOWED_HOSTS=localhost python manage.py collectstatic --noinput
DEBUG=False SECRET_KEY=local-test ALLOWED_HOSTS=localhost python manage.py runserver
```

(`gunicorn` does not run on Windows; Render runs it on Linux.)
